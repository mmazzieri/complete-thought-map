# complete-thought-map 1.0 (hybrid program) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `ctm`, the CLI "hybrid" program of Lion Kimbro's book (ch. VI, Geek Block), exactly as the approved design describes.

**Architecture:** A core library holds the domain (subjects, lists, entries, pages), the input parser, the engine that applies a parsed file atomically, the YAML store behind `INotebookStore`, and the `.txt`/`.docx` renderers. A thin CLI exe (`ctm`) wires commands to the core and writes receipts. Tests use xUnit against the core and run the CLI in-process.

**Tech Stack:** .NET 10 (SDK 10.0.300), C#, xUnit, YamlDotNet, DocumentFormat.OpenXml, System.CommandLine (or hand parsing — builder's choice).

**Spec:** `docs/superpowers/specs/2026-11-08-hybrid-v1-design.md` (Italian; section numbers §n below refer to it). Book extract: `docs/book-spec-extract.md`. Book: `book/book.txt`.

## Global Constraints

- Target `net10.0`; nullable enabled; warnings as errors in `src/`.
- Code license GPL-3.0: every source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later`.
- Program messages, identifiers, docs: English. README has an Italian section.
- Page capacity default **70**, columns **2**, font size **8** pt, paper **A4** (configurable `Letter`).
- Numbers never reused or renumbered; a list's `Next` only increases.
- Subjects sorted by **full name**, printed by full name; abbreviations matched case-insensitively and unique.
- Reserved subjects created by `init`: `UNPLACED` ("Unplaced"), `CHAOS` ("Chaos").
- Reserved words (cannot be abbreviations): `PAN NEW ADD EDIT NOTE CHECK UNCHECK RETIRE ARCHIVE START S POI P REF R`.
- An input file applies all-or-nothing; a file whose SHA-256 was already applied is rejected.
- No dependency on Microsoft Word being installed.
- Colors (docx): red `C00000` moved/retired marks, green `00803C` notes, blue `0050A0` numbers, black content.

## Review Focus

1. **Windows CRLF and a UTF-8 BOM in input files** — must parse identically to LF/no BOM (Task 2 test `Parse_CrlfAndBom_SameAsLf`).
2. **Pipes inside content** (`a | b` in the thought text) — content is everything after the third `|` (Task 2 test `Pan_ContentMayContainPipes`).
3. **A move of an already-moved or retired entry, or to an `old` subject, or to itself** — error with line number, nothing written (Task 3 test `Move_InvalidSources_Rejected`).
4. **Interrupted write / corrupt YAML** — atomic write leaves old file intact; `check` reports the bad file instead of crashing (Task 4 test `Save_IsAtomic_BackupKept`, `Load_CorruptYaml_ReportsFile`).
5. **Non-ASCII text** (Italian accents, `è`, `—`) round-trips through YAML, txt and docx (Task 4 `RoundTrip_Unicode`, Task 5 `Txt_Unicode`).

### Task 2: Input parser (§6)

**Files:** `src/Ctm.Core/Input/*`, `tests/Ctm.Tests/ParserTests.cs`.

**Interfaces (Produces):**
- `abstract record Request(int Line)` with subtypes: `PanRow(int Line, DateOnly Date, string? Subject, string? Hint, string? Psi, string Content)`, `MoveRow(int Line, string FromSubject, ListKind List, int Number, string ToSubject)`, `NewSubject(int Line, string Abbrev, string Name)`, `AddEntry(int Line, string Subject, ListKind List, string? Hint, string? Psi, string Text)`, `EditEntry(int Line, string Subject, ListKind List, int Number, string Field, string Value)`, `NoteEntry(int Line, string Subject, ListKind List, int Number, string Text)`, `CheckEntry(int Line, string Subject, ListKind List, int Number, bool Checked)`, `RetireEntry(int Line, string Subject, ListKind List, int Number)`, `ArchiveSubject(int Line, string Abbrev)`, `StartList(int Line, string Subject, ListKind List, int Next)`.
- `record ParseError(int Line, string Message)`.
- `static (IReadOnlyList<Request> Requests, IReadOnlyList<ParseError> Errors) InputParser.Parse(string text)`.

Grammar (decides what the spec §6 leaves to syntax):
- Normalize CRLF→LF, strip BOM. Lines starting with `#` (after trim) are comments. Blank lines end a block.
- A block whose first line starts with `PAN ` → date `yyyy-MM-dd`; following lines are rows split on the first three `|` into subject, hint, psi, content (each trimmed, empty → null; content required). A line starting with `+ ` appends `"\n" + rest` to the previous row's content; `+ ` as first row → error.
- A block whose first line is a single token that is not a reserved word, and whose second line is a single list code → move block; each following line `^\s*(\d+)\s+(\S+)\s*$`.
- Any other non-blank line: keyword line per the table in spec §6.3. `EDIT` field ∈ `content|hint|psi|title|citation` (`content`/`title`/`citation` all map to `Text`). `ADD … S` takes `| hint | psi | content`; `ADD … POI|REF` takes `| text`.
- Unknown keyword or malformed line → `ParseError` with 1-based line number; parsing continues to collect all errors.

- [ ] Step 1: tests: `Pan_ParsesRows` (spec §6.1 example verbatim → 3 `PanRow`s; second content = `"Subject pages should link to their REFs,\nand REFs should list the pages that cite them."`; third Subject null), `Pan_ContentMayContainPipes`, `Move_BookExampleVerbatim` (the 11 lines of book L6174-6184 → 9 `MoveRow`s, first `(MTK,S,13,Eth)`, last `(MTK,S,121,Spt)`), `Keywords_AllForms` (one line per §6.3 row → expected record), `Errors_HaveLineNumbers` (`ADD Eth X | a` on line 3 → error line 3; `+ x` as first PAN row → error), `Parse_CrlfAndBom_SameAsLf`, `Comments_Ignored`.
- [ ] Step 2: run → FAIL. Step 3: implement. Step 4: run → PASS. Step 5: commit `feat(core): input parser`.

### Task 3: Applier and page tracking (§5, §6, §7 "changed")

**Files:** `src/Ctm.Core/Engine/*`, `tests/Ctm.Tests/ApplierTests.cs`.

**Interfaces:**
- Consumes: Task 1 model, Task 2 requests.
- Produces:
  - `readonly record struct PageKey(string Subject, ListKind List, int Index)`; `static PageKey PageKey.For(string subject, ListKind list, int number, int perPage)` → `Index = (number-1)/perPage + 1`.
  - `sealed class PageTracker { Dictionary<PageKey,int> Revision; Dictionary<PageKey,int> Produced; void Touch(PageKey k); IReadOnlyList<PageKey> Changed(); void MarkProduced(IEnumerable<PageKey> keys); }` — changed = Revision > Produced (missing = 0).
  - `sealed class ApplyResult { bool Ok; List<ParseError> Errors; List<string> Log /* human lines for the receipt, e.g. "Ethics S57 added", "Mental Techniques S13 -> Ethics S57" */; List<PageKey> Touched; List<string> NewSubjects; }`.
  - `static ApplyResult Applier.Apply(Notebook nb, PageTracker pt, IReadOnlyList<Request> reqs, DateOnly today)` — validates and applies on a **deep copy**; commits into `nb`/`pt` only if no errors (all-or-nothing). Easiest: `Notebook.Clone()` via the YAML serializer from Task 4 is not available yet → implement `Notebook.DeepClone()` in Task 1 files.
- Rules: PanRow subject null → `UNPLACED`; unknown subject → error; subject `Old` → error on add/move-to; move: source must be `Live`, dest ≠ source subject; dest entry gets `MovedFrom`, `Date = today`, same hint/psi/text/notes; source becomes `Moved` with `MovedTo`; touches source page and dest page. Every mutation touches its page. `RETIRE` on non-live → error. `START` touches nothing.
